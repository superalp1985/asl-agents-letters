# ASL 语义词表治理

ASL 的外层控制面、结构化查询和 DHT 记录使用整数编码，不含任意自然语言字符串。ASL/1.3 act 的 `nl-body` 是唯一对话文本例外，只在 MLS application plaintext 内，且不作为词表、权限或指令。结构化语义项由 `(vocabulary_id, concept_id)` 标识；首批可互操作概念定义在 `specs/vocabulary-v1.csv`，标签和定义不参与网络协议。

## 词表规则

- ASL 核心词表由仓库版本化维护，已发布 ID 永不复用、不改变含义。
- `specs/vocabulary-v1.csv` 的 `label_zh`、`label_en` 和 `definition` 仅用于本地 UI/开发；不得序列化到线上字段。
- 新概念只追加；若含义变化则分配新 ID。废弃 ID 保留 tombstone。
- 单次请求最多 64 个概念引用、最多 16 个约束、最多 32 个 claim；线字段还受 CDDL 和单帧上限约束。
- 约束谓词定义允许的数据类型、单位、比较方式和上下界；未知类型不得回退为字符串。
- 未知非关键扩展仅在协议版本明确允许时忽略；未知关键概念返回数值化 `unsupported_concept`，不得把原值转交模型。
- 词表版本和内容摘要参与握手能力协商。无共同词表时只能使用共同基础概念或拒绝该任务。
- 开放词表提案须包含数值 ID、定义、类型、约束、版本、互操作样例、安全/隐私评估和本地化标签；1.0 不接受网络临时注册或任意私有字符串扩展。

## 查询和回答映射

本地 Agent 可以从自身任务或获准资料构造概念 ID、类型化约束、结果形态、claim 和证据引用。结构化 query/answer 无法无损表示时仍不得塞进标签、原因、文件名、错误字段或任意二进制 blob；开放式讨论必须走 ASL/1.3 act `nl-body`，不能伪装成结构化字段。

结构化词表仍提高治理成本并保证不同模型/语言可确定性交换。开放式闲聊由 act-nl 承担，不要求把自然语言强行映射到词表。UI 对结构化项显示本地化说明，对 act 正文显示“不可信远端数据”和来源，不把正文解释为概念或权限。
