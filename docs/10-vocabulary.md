# ASL 语义词表治理

ASL/1 的网络消息使用整数编码，不含自然语言字符串。每个语义项由 `(vocabulary_id, concept_id)` 标识。首批可互操作概念定义在 `specs/vocabulary-v1.csv`；本机 UI 按其中的本地化标签显示人类可读名称。标签和定义不参与网络协议，也不作为 Agent 指令。

## 词表规则

- ASL 核心词表由仓库版本化维护，已发布 ID 永不复用、不改变含义。
- `specs/vocabulary-v1.csv` 的 `label_zh`、`label_en` 和 `definition` 仅用于本地 UI/开发；不得序列化到线上字段。
- 新概念只追加；若含义变化则分配新 ID。废弃 ID 保留 tombstone。
- 单次请求最多 64 个概念引用、最多 16 个约束、最多 32 个 claim；线字段还受 CDDL 和单帧上限约束。
- 约束谓词定义允许的数据类型、单位、比较方式和上下界；未知类型不得回退为字符串。
- 未知非关键扩展仅在协议版本明确允许时忽略；未知关键概念返回数值化 `unsupported_concept`，不得把原值转交模型。
- 词表版本和内容摘要参与握手能力协商。无共同词表时只能使用共同基础概念或拒绝该任务。
- 开放词表提案须包含数值 ID、定义、类型、约束、版本、互操作样例、安全/隐私评估和本地化标签；1.0 不接受网络临时注册或任意私有字符串扩展。

## 查询和回答映射

本地 Agent 可以从自身任务或获准资料构造概念 ID、类型化约束、结果形态、claim 和证据引用。任何无法无损表示的自然语言细节都不发送；不得把它塞进标签、原因、文件名、错误字段或任意二进制 blob。

这会牺牲开放式闲聊能力并提高词表治理成本，但允许不同模型和语言使用相同协议。UI 可将已知结构渲染成本地化说明；无法渲染的内容仍显示类型码和来源状态，不臆造含义。
