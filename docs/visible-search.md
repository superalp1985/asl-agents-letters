# Local permission-filtered search

The importer indexes a resource reference, not a content hash. Two references to identical bytes may have different audiences and annotations. Imports index only the basename and the first 32 KiB of eligible UTF-8 text read from the same pinned stream as the snapshot. PDF and binary formats are title-only; enrichment accepts bounded, already-extracted local text for a specific reference and content ID. No PDF parser, model, cloud service or network endpoint is enabled here. Reimport fills a missing old index but does not overwrite enrichment. Rust source files receive frozen topic `(1,101)`; arbitrary prose is not converted into topic IDs.

`Store::peer_search` requires a T07 device-bound policy scope and a matching AgentId, not a claim from the wire. `visible_keys` consults the live grant, snapshot, resource epoch, SQL audience and the policy engine. `search_visible` repeats authorization even for caller-supplied keys, and requires both Search and ReadMetadata. Only then does FTS5 match individual authorized row IDs. Text scoring boosts matches in the title, not by global corpus statistics. Ties use a stable resource key. Hits carry local metadata, no filesystem path, body, model-input permit or transfer lease.

The structured API accepts known frozen topic IDs. The separate local text API tokenizes Chinese with [jieba-rs](licenses/jieba.txt) and treats SQL and MATCH operators as literal words. Local text, scores and titles must not be forwarded as protocol fields. Queries accept at most 4,096 candidate keys and return at most 64 results; exceeding either limit is an error, not silent truncation.

For larger libraries Core can use `visible_keys_page` with a bounded physical-row budget. A local continuation or even an empty page may reflect private rows: never send these cursors, quota errors, or intermediate counts to peers. A database change may require restarting the scan. Durable registry revocations veto a cached device scope; a registry sequence change or checkpoint replacement invalidates its old policy revision. A permission that changes while returning a ranked result requests a retry, not a partial result.

SQLite migration v3 removes stale local index entries; transactional triggers retire each local index when its reference is invalidated or deleted or its grant is revoked. This removes live FTS rows, not forensic remnants in disk pages, WAL files or backups.

The fixture for contacts-only PDF body search supplies already-extracted local text. This is not evidence of PDF extraction, a live authenticated peer, a working group chat, timing-side-channel resistance, or Internet file transfer. The future Core handler must populate fresh identity/policy facts and perform separate model or send-time authorization. Inbox and derived material are not searched by this local-import adapter.
