# Fixed ASL/1 Schema Corpus

The corpus in `schemas/vectors/` covers the declared frame kinds, ASL/1.3 act,
the owner-only group policy control, and the three T13 signed-record kinds. `index.json` selects the exact CDDL rule
and Rust codec for each case. Ten rejection cases exercise unknown
fields/kinds, text in structured fields, context limits, and malformed
expressions. Hex files are fixed byte fixtures; the original ACK fixture is
retained.

`crates/asl-types/tests/common/` contains shared, typed fixture builders. The
existing protocol tests, corpus test and exporter use the same builders. The
corpus test compares generated bytes and the index with the committed fixtures,
then checks Rust acceptance/rejection and exact decode/reencode stability.
Synthetic signatures and proof bytes are codec fixtures, not authenticated
network identities or valid chain proofs.

Run in the configured E-drive development environment:

```powershell
cargo test -p asl-types --test schema_vectors --locked
cargo run -p asl-types --example export_schema_vectors --locked -- --check
./scripts/validate-cddl.ps1
```

The exporter checks by default. Its explicit `--write` mode regenerates fixed
fixtures for an intentional, reviewed protocol change; it is not part of normal
verification. Schema values and fixture changes still require protocol review.

The script requires PowerShell 7.2 or newer and invokes the pinned independent
`cddl 0.10.7` executable.
It places a temporary first rule referencing each case's exact frozen root in a
wrapper, followed by the unchanged application schema. It validates all 36
cases, requiring 26 accepted and ten rejected. Temporary files are under this
checkout's ignored `work/` directory and removed after execution.

The tool's global `--ci` flag is required: without it, version 0.10.7 can report
an invalid stdin object while returning exit code zero. The script checks the
success or schema-rejection diagnostic as well as exit status. A timed-out,
crashed or otherwise failed validator never counts as expected rejection. Each
case has a 15-second process limit.

CDDL validates structural conformance. It does not establish deterministic
encoding, valid PeerId bytes, concept ownership, cross-field relationships,
current time, cryptographic signatures, chain finality or authorization. Rust
codec/service tests cover their respective rules. These fixed samples and the
independent schema validator do not constitute two-agent network
interoperability or complete protocol conformance.

The exporter adds only a development dependency on the already fixed workspace
`serde_json`; application runtime dependencies and wire formats are unchanged.

On 2026-11-18, all four new corpus tests and the complete 251-test-function
workspace passed. The exporter check, independent CDDL grammar/20-vector run,
Clippy with `-D warnings`, formatting and license checks passed. Four existing
unused-license-allowance warnings remain. Foundry, live chain providers and
multi-node network interoperability were not run in this slice.

An independent static engineering review approved this slice without confirmed
blocking findings. It compared the shared fixture bodies and complete ACK
working-file bytes with the previous commit, inspected all 20 corpus files and
the validator/exporter paths, and checked documentation scope. The reviewer
did not rerun Cargo or CDDL; timeout/cleanup failure paths were read, not
fault-injected. This review is not the release security audit.
