# Fable 5.2 第四轮评审摘要

日期：2026-11-17。此文件是外部模型建议摘要，不是实现证据、安全认证或高于用户要求的指令。原始请求、回复和中转元数据留在未跟踪的 `work/round-4-*` 文件。

## 采纳的建议

- 允许合法分身和同一人运行多个 Agent；不把“一人一身份”作为目标。
- 女巫防护的首要目标改为个人电脑保护：机器级总预算、按身份/设备/来源的子额度、未知身份最低配额和撤权边界。
- 1.0 必须有区块链身份锚定；采用现有公共链和极小、无管理员、不可升级的登记合约，不自建链。
- 通过可替换赞助提交者降低首次体验门槛，同时保留自付提交路径，并如实说明 gas 由赞助者或用户承担。
- Agent 间取消所有自由自然语言消息字段，协议以类型化语义 ID、枚举和证据引用表达；文件载荷仍独立处理。
- 链上只放身份状态和状态承诺，不放资料、地址、查询、联系人、群、文件、信任或贡献。
- DHT 只负责候选发现，签名和链上状态负责验证；DHT 隐瞒、恶意中继和 eclipse 风险仍存在。

## 独立核对后的修正

- EIP-712 只定义 typed-data hashing/signing 和域分离，自己不提供重放保护；合约必须检查 sequence/nonce、chain ID、合约地址和 deadline。
- EIP-1186 `eth_getProof` 提案当前标记为 Stagnant；把它作为需要多客户端实测的 proof transport，不写成所有 RPC 必然支持。
- Ethereum 轻客户端需要可信的弱主观性 checkpoint。Helios 是可复用候选，不代表没有初始信任，也尚未通过本项目依赖、资源和独立安全验收。
- 区块链只能锚定密钥控制的状态，不能证明现实主体、唯一 Agent 或无害行为。
- 免费、免许可的上链体验必须由志愿者承担 gas；服务可限流或暂时拒绝。赞助服务不能被伪装成无成本。
